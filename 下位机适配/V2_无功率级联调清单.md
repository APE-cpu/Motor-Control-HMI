# v2 无功率级联调清单

> 目标：只给控制板、通信接口和必要传感器供电，不连接500V直流母线，不使能栅极驱动，不连接电机。验证通信协议和软件安全闭环，不验证功率级能力。

## 一、接入前代码检查

- 将`v2_protocol_portable.h/.c`加入STM32或C2000工程；先只接串口，暂不接经典CAN。
- 参考`platforms/adapt_v2_stm32_hal.c`或`adapt_v2_ti_c2000.c`建立UART/SCI适配。
- RX中断只写环形缓冲；`v2_proto_feed_byte()`在主循环或低优先级通信任务运行。
- 实现`app_v2_command()`，所有危险命令先经过本机状态和保护门禁。
- START在栅极未允许、母线未预充、驱动故障未清除或状态不正确时必须NACK。
- STOP、EMERGENCY_STOP和RESET_FAULT分别定义清楚；RESET_FAULT不得绕过仍然存在的硬件故障。
- 设备ID必须唯一且固定；固件、硬件版本随构建和板卡修订更新。
- 首轮波特率建议115200 8N1，设备地址使用1，上位机心跳0.5秒、ACK超时1秒。

## 二、固件自检

1. 验证`v2_proto_crc16("123456789", 9) == 0x29B1`。
2. 上电后功率使能输出保持禁止，PWM输出关闭。
3. 未收到HELLO时发送COMMAND，设备返回错误码100的NACK。
4. 收到HELLO后返回CAPABILITIES，确认设备ID、版本、命令表和遥测字段正确。
5. 故意输入错误CRC、错误帧尾、超长payload和随机噪声，固件不得跑飞；后续正常HELLO仍能恢复。
6. 观察RX环形缓冲溢出计数，正常握手与遥测期间必须保持0。

## 三、上位机连接步骤

1. 上位机通信页选择RS-232或RS-485，填写端口与115200 8N1。
2. 协议模式选择`negotiated-v2（真实握手）`。
3. 点击连接，确认会话为READY，并核对设备ID、硬件、协议和固件版本。
4. 确认协议统计中握手次数为1，CRC/帧错误为0，心跳ACK持续增长。
5. 此时仍保持PWM和栅极禁止；不要仅因为上位机READY就使能功率级。

## 四、必须执行的故障场景

| 编号 | 操作 | 预期结果 |
|---|---|---|
| V2-01 | 正常连接 | HELLO/CAPABILITIES完成，会话READY |
| V2-02 | 发送合法但当前不允许的START | 设备NACK，上位机不进入RUNNING |
| V2-03 | 发送STOP | 设备ACK；设备安全输出仍保持禁止 |
| V2-04 | 发送EMERGENCY_STOP | 设备进入保护锁定并ACK，故障遥测可见 |
| V2-05 | 故障条件仍存在时RESET_FAULT | 设备NACK，不清除保护 |
| V2-06 | 清除模拟故障后RESET_FAULT | 设备ACK并回到允许预检状态 |
| V2-07 | 连续遥测至少30分钟 | 无解析崩溃、无RX溢出、CRC错误为0 |
| V2-08 | 通信中按控制板复位键 | 1.5秒内上位机会话失效；若处于RUNNING则FAULT_LOCKED |
| V2-09 | 拔掉串口/断开USB转串口 | 上位机报告链路或心跳失效，不自动重连并复位故障 |
| V2-10 | 注入错误CRC帧后恢复正常帧 | 错误计数增加，后续帧正常解析 |
| V2-11 | 将设备协议范围改为不含2 | 握手失败，不降级v1 |
| V2-12 | 使用错误设备地址 | 设备忽略，上位机握手超时 |

## 五、记录要求

- 每次测试建立独立实验记录，备注固件Git版本、板卡版本、串口适配器和波特率。
- 保存通信页协议统计、操作事件和故障原因；关键场景保留逻辑分析仪或串口抓包。
- 任一“命令已NACK但硬件动作”“通信失效后仍允许启动”“复位自动解除故障锁定”均为阻断问题。

## 六、进入低压功率级测试的门槛

- V2-01至V2-12全部通过并可重复。
- 连续30分钟无RX溢出、后台任务卡死或无法恢复的协议错误。
- START/STOP/急停/故障复位的ACK语义由上位机和固件负责人共同确认。
- 控制板复位、拔线和上位机退出时，PWM及栅极使能均回到经硬件验证的安全状态。
- 先进入隔离低压直流母线测试；不得从无功率级联调直接跳到500V平台。
