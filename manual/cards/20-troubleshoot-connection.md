# 连接失败 / ACK 超时 {#troubleshoot-connection}
> 分组：排障 · 页面：communication · 耗时：约 5 分钟 · 风险：排查期间不要带功率反复重启
> 关键词：连不上, 握手失败, 握手超时, 未连接, ACK超时, 超时, 断开, 心跳, 身份不符, NACK

## 步骤
1. 按 Ctrl+K 输入 `state`，看连接状态、协议模式和遥测时延
2. 在“通信设置”确认链路类型和端口/IP，协议为 negotiated-v2 {控件: communication.protocol}
3. 断开后重新连接一次，观察状态栏的失败原因 {控件: communication.connect}
4. 打开“操作记录”页，查看最近的握手、NACK 和超时记录

## 预期
能定位到是物理链路、协议选择、设备身份还是命令拥塞的问题。

## 失败时
| 症状 | 最可能的原因 | 处理 |
|---|---|---|
| 一直未连接、握手超时 | 线缆/网段/端口不对；控制板固件不支持 v2 | 检查物理链路与 IP；确认固件版本 |
| 握手后立刻断开 | 设备身份与实验档案不符 | 在实验页选择正确的设备档案修订 |
| 连接后隔一会儿断开 | 心跳 1 s 内无应答：设备重启、链路不稳 | 看操作记录中的会话失效原因 |
| 单条命令 ACK 超时 | 同一时刻连发多条命令（如遥测配置紧接启动） | 两条命令分开发送，等上一条 ACK |
| 2~16 kHz F1 报错 | 串口/RS-485/CAN 带宽不足 | 改用以太网 TCP |

任何握手失败、身份不符或 ACK 超时，都先查原因，**不要反复尝试带功率重启**。

## 原理与公式
- 只有收到兼容的 CAPABILITIES 才算连接成功；超时、版本不兼容或错误设备都保持失败，不会自动降级到 v1。
- 心跳周期 0.5 s、应答超时 1 s；会话失效时上位机退出 READY，并清空全部待应答命令。
- 协议统计（发送/接收帧、CRC 错误、ACK、NACK、超时、迟到 ACK、握手与会话失效次数）在通信页只读显示，用于事后追溯链路质量。
