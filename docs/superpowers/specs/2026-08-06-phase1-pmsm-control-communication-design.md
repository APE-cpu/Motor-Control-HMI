# 阶段一：PMSM 控制与通信边界重构设计

日期：2026-08-06  
范围：上位机中间层（PMSM 控制、通信入口）及其与实验管理、下位机诊断层的边界

## 1. 目标与非目标

### 目标

1. 将中间层收敛为“PMSM 控制 + 可审计通信”，控制页不再承担设备档案、一次性传感器配置或实验负载建模。
2. 移除双凸极电机和直线电机的运行入口，保证新建配置、控制模式过滤、报文元数据和页面状态中不再出现这两类电机。
3. 把电机铭牌/设备详情归实验管理，把实体位置传感器配置、自检和详情归新的“诊断与标定”页。
4. 将无位置传感器作为控制算法保留在中间层，并提供原理、参数、调试信号和安全门槛，而不是把它当作一次性传感器配置。
5. 将负载类型作为实验/数字孪生元数据；真机控制不得因为选择“负载电机”或“磁粉制动器”而下发任何新增报文。
6. 保持旧实验记录和旧配置可读，修改失败时能够恢复到 v1.8.0 的页面和数据结构。

### 非目标

- 本阶段不实现新的 MPC、ESO、RLS、KF 或神经网络算法。
- 本阶段不改变下位机协议字段的物理含义，不把负载类型加入协议。
- 本阶段不删除已有仿真负载模型；仿真模型只改变配置入口和真机隔离边界。
- 本阶段不彻底删除旧 SRM 控制器文件，以免历史导入、旧报告或外部脚本导入时崩溃；它们将失去运行入口并标记为遗留代码。

## 2. 当前耦合与风险

当前 `pages/control_page.py` 同时持有：

- 电机类型、最高转速、电流限幅和电机详情入口；
- 实体传感器与无位置算法的混合选择树；
- 传感器详情/自检入口；
- 负载类型、机械参数和仿真扰动按钮；
- 控制器选择、参数下发和实验快照生成。

`config/config.py` 还把 PMSM、双凸极和直线电机放在同一套电机类型映射中；实验页、控制页测试和报告快照直接读取控制页控件。直接删除控件会造成空引用、旧 JSON 无法加载、实验报告字段丢失，甚至让旧控制器在导入时被错误调用。

因此采用兼容迁移：先建立新的数据所有权和适配层，再切断 UI/运行入口，最后删除冗余字段和文档暴露。

## 3. 目标页面职责

### 3.1 PMSM 控制页（中间层）

只保留本次运行真正需要的控制内容：

- 运行命令：启动、停止、复位、目标速度/转矩/电流；
- 控制策略：PI/FOC、开环、MPC、无模型控制、无位置控制等 PMSM 策略；
- 当前策略参数及其单位、范围和修改来源；
- 运行约束：本次实验生效的最高转速、Iq/电流限幅和失控阈值；
- 无位置算法调试区：方法、适用速度区间、输入信号、观测器参数、估计角与物理传感器真值对比、残差/收敛度和安全状态；
- 通信结果：参数版本、ACK、超时、拒绝原因、最近一次下发时间。

控制页不再包含电机类型选择、电机详情按钮、实体传感器自检、机械负载选择或机械参数输入。

### 3.2 实验管理页（上层）

实验管理成为设备与实验方案的唯一档案入口，包含：

- 电机铭牌与设备档案：型号、额定功率、电压、电流、转速、极对数、Rs、Ld/Lq、磁链、驱动板、固件版本等；
- 实验运行约束的初始模板；控制页可以在本次实验中修改运行约束，修改结果写入实验快照；
- 负载/机械配置：空载、负载电机、磁粉制动器、其他负载，以及数字孪生需要的 J/B/Tc 和负载模型参数；
- 真机/仿真模式标识。真机模式保存负载选择为实验元数据，数字孪生模式才将负载模型传给仿真对象。

“最高转速”和“电流限幅”不再作为电机详情字段展示。设备档案只保留“额定”铭牌信息；实际本次实验使用的运行上限由控制页维护，固件硬保护通过通信状态只读显示。

### 3.3 诊断与标定页（下层）

第一阶段先建立最小可用页，并完整承接现有实体传感器能力：

- 选择和保存 Hall、QEP、Resolver 等实体位置传感器配置；
- 传感器详情、接线/信号说明、在线自检和结果记录；
- 一次性校准：零位、方向、极性、计数器、采样漂移和质量阈值；
- `CMD_SET_SENSOR` 的唯一操作入口；
- 与下位机返回值的匹配检查，保存配置版本和校准时间。

控制页只读取诊断页的“已验证传感器摘要”，不重复配置，也不在启动时悄悄改变传感器参数。若下位机重启导致配置失效，用户必须在诊断页明确执行“重新应用”。

## 4. 数据所有权与兼容策略

新增或明确以下四类数据边界：

| 数据 | 唯一所有者 | 真机行为 | 数字孪生行为 |
|---|---|---|---|
| `MotorProfile` | 实验管理 | 设备档案与铭牌，只读引用 | 作为模型参数来源 |
| `ControlRuntimeConfig` | PMSM 控制页 | 下发控制参数和运行限幅 | 驱动仿真控制器 |
| `SensorCalibrationProfile` | 诊断与标定页 | 通过明确动作下发并核验 | 作为传感器模型/真值来源 |
| `LoadSetup` | 实验管理/数字孪生 | 只写实验记录，不进入真机报文 | 选择并配置仿真负载 |

旧配置加载时：

- `motor_type` 为双凸极或直线电机时，转换为“遗留类型（不可运行）”，保留原始字符串用于历史报告，不抛异常；
- 旧控制页中的 `max_rpm`、`iq_max`、`max_current_a` 迁移为 `ControlRuntimeConfig`；
- 旧的 `load_type`、J/B/Tc 迁移到 `LoadSetup`；
- 旧的传感器字段迁移到 `SensorCalibrationProfile`，但只有实体传感器配置可自动视为已保存，无位置算法参数必须由控制页重新确认；
- 新保存格式只生成 PMSM 和新的四类数据结构，不再写入 SRM/直线电机运行字段。

迁移过程必须可重复、幂等，并在实验报告中保留“由旧版本迁移”的标记。

## 5. 电机类型与旧控制器处理

- `MOTOR_TYPES` 的新建选择只保留 PMSM。
- PMSM 的控制方式和传感器过滤逻辑单独定义，不再通过电机类型分支进入 SRM/直线电机控制器。
- 删除控制页对 `current_chopping_controller.py`、`angle_position_controller.py`、`voltage_control_controller.py` 的导入和运行入口；旧文件暂留在遗留目录或原路径并加弃用说明。
- 协议解码层可以继续识别历史 `motor_type` 字符串，以便打开旧记录，但不得把它们重新暴露为可启动控制模式。
- README、使用说明书、软件介绍、通信数据字典和测试夹具同步改为“当前支持 PMSM；其他类型仅作历史兼容”。

这里的“清理干净”定义为：新用户界面、控制运行时、状态摘要和新报文路径均不可到达双凸极/直线电机；待历史数据迁移完成后，再单独安排物理文件删除。

## 6. 通信安全边界

通信层保持现有协议兼容，但增加三条约束：

1. 真机控制报文只允许来自 `ControlRuntimeConfig` 和已验证的控制算法参数；负载类型、机械参数和设备详情不能进入控制报文。
2. `CMD_SET_SENSOR` 只能由诊断页显式触发，并要求 ACK、超时和拒绝原因可见；控制页不得在切换算法时隐式发送实体传感器配置。
3. 每次下发前记录参数版本、目标设备 ID、通信序号和结果；失败时保留界面当前值与下位机已确认值的差异，不假装成功。

启动前置检查至少包括：设备 ID 匹配、固件能力声明为 PMSM、传感器配置已验证、运行限幅非零且在固件硬限值内、通信心跳正常。任一项失败时禁止启动命令。

## 7. 分阶段实施与回滚

实施顺序：

1. 新增数据适配器和诊断页壳，先让旧控件与新数据双向映射；
2. 将实体传感器详情/自检迁移到诊断页，加入旧配置读取和诊断摘要；
3. 将电机档案、负载配置和实验快照改由实验管理维护；
4. 控制页切换为 PMSM-only，移除 SRM/直线电机入口和负载控件；
5. 清理文档、状态摘要、日志和通信描述；
6. 运行全量测试、旧配置回放和真机报文断言，再考虑删除遗留文件。

每一步都单独提交。开始修改前保存 v1.8.0 的工作树基线和关键配置导出；任一步验收失败时只回滚最近一步，不覆盖用户已有实验数据。

## 8. 测试与验收标准

必须新增或更新以下测试：

- PMSM 是唯一可新建电机类型；旧 SRM/直线电机配置可读但不可启动；
- 控制页不存在电机详情、实体传感器自检和负载选择控件；
- 诊断页能够打开实体传感器详情、自检并保存配置；原有 `CMD_SET_SENSOR` 编码和 ACK 处理不回归；
- 无位置算法面板仍可选择、加载参数、显示说明和调试状态；
- 真机选择负载类型不产生任何新增下发帧；数字孪生选择负载仍能驱动现有仿真；
- 实验快照包含设备档案、运行限幅、传感器校准摘要和负载元数据，旧快照可加载；
- 控制参数下发只包含允许的控制字段，超时、拒绝和设备不匹配均能阻止启动；
- 全量 `pytest`、应用导入检查和至少一次手动启动/停止回归通过。

完成定义：新建实验只能创建 PMSM；控制页职责单一；诊断/实验管理页接管各自数据；真机不因负载元数据下发额外命令；旧实验文件仍能打开；失败可以回退到 v1.8.0。
